# Printed Seytek page 985 reading order: evidence and repair plan

Date: 2026-09-24. This is a plan, not a change to the canonical release.

## Finding

The current batch and release put `seytek-2012:p0985:b002:l001` through `b002:l040` before `b003:l001` through `b003:l039`. Rendering `sources/raw/seytek-2012.pdf` page 985 shows `b003` on the **left** and `b002` on the **right**. Their source coordinates independently agree: `b003:l001` begins at x=79.44, `b002:l001` at x=310.2. The page should be read left to right, `b003` then `b002`.

Printed textual joins support the visual order: page 984 ends `Күйүтүң өттү ушундай.` then page 985 left begins `Таш майданда чабыштың,`; page 985 left ends `Минтип жанын күйгүзүп,` then right begins `Сынчыларга каратып,`; page 985 right ends `Күйгүзгөнү чочконун,` then page 986 left begins `Сөксөөлдүн чогундай,`. The last pair completes the comparison of the swine's burning words to a saxaul ember. The local release ordinals 372533–372611 currently follow `b002` then `b003` and are wrong in narrative order.

Do **not** use `research/working/current142/page-119.reviewed.jsonl` or `page-120.reviewed.jsonl` as confirmation. Direct inspection of manuscript PDF 142 page 119 found the physical count `53` and its lower lines still in the printed page 984 passage. The saved draft has 63 rows and falsely carries printed page 985 lines onto that leaf. PDF 142 page 120 likewise begins with words different from its saved row 1. Those draft crosswalks need separate correction.

## Smallest safe page 985 repair

Keep `sources/extracted/seytek-2012.lines.jsonl` untouched: it preserves the raw `pdftotext` extraction order, coordinates, and the `research/line-extraction.json` digest. A direct edit to that file would be undone by `scripts/extract.py` and would require digest regeneration. Add a helper that presents the reviewed source order to consumers while retaining the extraction record for each ID.

Update the order comparisons in `scripts/check-alignment.py`, `scripts/audit-drafts.py`, `scripts/append-translation.py`, `scripts/insert-translation.py`, and `scripts/apply-gap-first-pass.py` to use the same reviewed source sequence; inspect any other consumer that assumes extraction JSONL order before expanding the override. Reorder `pages-seytek-0985.en.txt` by **ID-English pairs**, preserving each translation with its source ID. Do not rotate English text alone. Keep notes/review records attached by ID. Change `corpus/batches/pages-seytek-0986.json` `after_id` from `p0985:b003:l039` to `p0985:b002:l040`; page 985 `after_id` remains page 984 `b003:l040`. Use a constrained one-time release reorder operation: assert the existing 79-row window contains exactly the page 985 IDs in current order; permute whole row objects by the reviewed ID sequence; rewrite their `ordinal` fields to the contiguous 372533–372611 window; assert all other row IDs/ordinals and every row's `en`, `ky`, `source` and review metadata are unchanged; then call `write_release`. Add a focused regression test asserting page 985's left-before-right ID sequence, its original source ID-English pairings, its release ordinals, and the page 986 `after_id`. Check gap markers and completeness remain unchanged. Only then include the repair in a local checkpoint; publication still requires the full trilogy's verified completeness.

## Broad reversal risk and migration scope

The read-only coordinate audit in `scripts/audit-seytek-column-order.py` found **667** two-column Seytek page batches whose current first block is on the right (among **1,094** two-block pages). The 0–699 page ranges account for 615 of these. Page 985 is therefore not an isolated extraction pattern. Pages 26, 744, and 985 have visually confirmed narrative-order errors; page 104 is a left-first control. Additional textual spot checks of pages 100, 500, and 700 show plausible left-to-right joins. This is enough to prioritize a corpus-wide audit, **not** enough to automatically reverse all 667 pages.

A 667-page migration is mechanically tractable because source IDs are stable and each page can be permuted without changing row counts or source evidence. The review burden is substantial: some pages have drop caps, extra blocks, headings, gaps, or already-correct order. Build a candidate map from coordinates; visually inspect each candidate page and its adjacent-page and inter-column joins; record accepted block order and exceptions; migrate audited page cohorts with per-ID English pair preservation and contiguous ordinal rewriting; run full alignment and draft audits after each cohort. Do not apply a global `b003,b002` rule or globally swap columns. The ordinary extraction order is a software artifact and cannot itself settle narrative order. Any page-specific uncertainty should remain open rather than be silently reordered.
